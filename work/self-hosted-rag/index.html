Work / Mother / Hermes

Mother / Hermes: a self-hosted RAG platform that treats its index as disposable

Why the vector index is derived state, why embeddings never leave the machine, and what that costs.

Role
Architect and operator, end to end
Status
In production on my own infrastructure
Stack
Qdrant, Ollama, LangGraph, MCP, LangFuse, Python, Linux
Source
Private. Walkthrough on request

Problem

I wanted retrieval over several separate bodies of knowledge that I could run myself: no documents or queries sent to a third party, no bill that grows with every question, and no silent degradation when something underneath breaks.

Constraints

  1. 01. Data and queries stay on my own machines
  2. 02. Zero cost per query, no rate limits
  3. 03. Knowledge domains must not leak into each other
  4. 04. Reachable only over a VPN
  5. 05. Any piece can be rebuilt after a failure

Decisions

Each one has a cost. Here is what I picked and what I paid for it.

Isolation

One Qdrant collection per domain

Why

A query against one domain can never surface another domain’s passages, and each collection can be rebuilt on its own.

Cost

More collections to operate, back up and rebuild.

Embeddings

Local, with Ollama and nomic-embed-text (768d)

Why

Zero cost per query, no rate limits, and embeddings that never leave the machine.

Cost

RAM and CPU per batch. The right trade for this workload.

State

The vector index is derived, rebuildable state

Why

Source files are the truth. When a collection was corrupted, I recovered it by rebuilding from source.

Cost

Re-embedding takes time, so rebuilds are rehearsed rather than improvised.

Observability

Self-hosted LangFuse

Why

Full traces of every retrieval and generation, kept on my own infrastructure instead of a SaaS endpoint.

Cost

Four more services to run: ClickHouse, Postgres, MinIO and Redis.

Agents

Bounded delegation that fails closed

Why

Depth-one spawning, capped concurrency, and leaf agents that cannot delegate or write memory. If a delegated provider is down, the work falls back inline.

Cost

Less autonomy by design: deep agent chains are not possible.

Memory access

Read-only MCP bridges, separate write path

Why

Workspaces query memory through MCP tools (search, grep, get, list collections). Writes are auditable Markdown files that a background daemon validates, chunks and indexes.

Cost

Writes are asynchronous: new knowledge appears after the sync, not instantly.

Access

WireGuard-only boundary

Why

Nothing is exposed to the public internet; nginx and systemd services sit behind the VPN.

Cost

Every client needs a VPN peer.

Architecture

Everything below runs behind a WireGuard boundary. Source files are the only state that matters.

Results

Multi-Domain

isolated vector collections

768d

local nomic-embed-text vectors

0

external embedding API calls

Measured on the running deployment. A corrupted collection was recovered by rebuilding it from source, which is why I argue that reindexing is a feature, not a failure.

What I would do differently

I built the infrastructure before the measurement layer. It has traces and recovery drills, but not yet a golden set that says how good retrieval actually is. Next time that comes first, and it is what I am building now: a retrieval benchmark with recall@k, latency percentiles and cost per query.
